## Назначение проекта

Программа анализирует введённое пользователем целое число и выводит набор его
характеристик: знак, чётность, делимость на 3 и 5, простоту, количество цифр
и то, является ли число полным квадратом.

Цель работы — освоить базовый синтаксис Python (условные конструкции, циклы,
обработку исключений), а также работу с системой контроля версий Git
и удалённым репозиторием на GitHub.

Все программы решают общие задачи:

- принимают данные от пользователя через консоль;
- анализируют число по семи характеристикам;
- обрабатывают некорректный ввод (не целое число);
- позволяют анализировать несколько чисел подряд без перезапуска программы.

Внешние библиотеки не используются — только стандартная библиотека Python.

## Вариант 3. Проверка характеристик числа

**Из практической работы №1:** программа анализировала одно введённое число.

**Новое в практической работе №2:**

1. возможность анализировать **несколько чисел подряд** без перезапуска программы;
2. добавлено определение, **является ли число квадратом целого числа** (полным квадратом).

**Определяемые характеристики:**

| Характеристика | Как определяется | Пример |
| -------------- | ---------------- | ------ |
| Положительное / отрицательное / ноль | Сравнение с нулём | `-7` → `нет (отрицательное)` |
| Чётное или нечётное | Остаток от деления на 2 | `120` → `да` |
| Делится ли на 3 | Остаток от деления на 3 | `120` → `да` |
| Делится ли на 5 | Остаток от деления на 5 | `120` → `да` |
| Простое ли число | Перебор делителей до `√n` | `17` → `да`, `49` → `нет` |
| Количество цифр | `len(str(abs(n)))` | `-7` → `1` |
| Полный квадрат | `int(n ** 0.5) ** 2 == n` | `49` → `да` |

**Как пользоваться программой:**

1. Введите целое число (положительное, отрицательное или ноль).
2. Программа выведет все характеристики числа.
3. На вопрос `Проверить ещё одно число? (да/нет):` ответьте `да`, чтобы продолжить,
   или любым другим текстом, чтобы завершить работу.

**Пример работы:**

```
Введите число: > -7
Ваше число: -7
Положительное: нет (отрицательное)
Четное: нет
Делится на 3: нет
Делится на 5: нет
Простое: нет
Количество цифр: 1
Полный квадрат: нет

Проверить ещё одно число? (да/нет): > да

Введите число: > 17
Ваше число: 17
Положительное: да
Четное: нет
Делится на 3: нет
Делится на 5: нет
Простое: да
Количество цифр: 2
Полный квадрат: нет

Проверить ещё одно число? (да/нет): > да

Введите число: > 49
Ваше число: 49
Положительное: да
Четное: нет
Делится на 3: нет
Делится на 5: нет
Простое: нет
Количество цифр: 2
```

## Особенности реализации

### Программа корректно работает с отрицательными числами

Раньше при вводе отрицательного числа программа падала. Причина была в проверке
на простоту: выражение `Number ** 0.5` для отрицательного числа даёт **комплексное**
число, а `int()` от комплексного вызывает `TypeError`:

```
Введите число: -7
Ваше число: -7
Положительное: нет (отрицательное)
Четное: нет
Делится на 3: нет
Делится на 5: нет
TypeError: int() argument must be a string, a bytes-like object or a real number, not 'complex'
```

Обратите внимание: строка `IsSimple = Number > 1` от падения **не защищала** — она
только вычисляла флаг, но цикл `for` выполнялся всё равно. Исправление
(коммит `24ad072`) заключается в том, что цикл выполняется только при `IsSimple == True`:

```python
#Проверка на простое число
IsSimple = Number > 1
if IsSimple:
    for i in range(2, int(Number ** 0.5) + 1):
        if Number % i == 0:
            IsSimple = False
            break
```

Теперь для отрицательных чисел, нуля и единицы цикл не запускается, `IsSimple`
остаётся `False`, и программа выводит `Простое: нет`. Проверка на полный квадрат
тоже защищена условием `Number >= 0`, поэтому `Root = int(Number ** 0.5)`
вычисляется только для неотрицательных чисел.

Проверено на значениях `-7`, `-4`, `0`, `1`, `2`, `5`, `49`, `120` — программа
завершается корректно во всех случаях.

### Исключения Git настроены

Файл исключений лежит в репозитории под именем `.gitignore` — с точкой в начале,
как и требуется. В него добавлены `__pycache__/`, `*.pyc`, `.vscode/`, `.idea/`
и `*.pdf`, поэтому служебные файлы Python и настройки редакторов в репозиторий
не попадают.

В истории коммитов файл сначала назывался `gitignore` без точки (коммит `ff3a49b`),
и в таком виде он **не работал**: Git читает только `.gitignore`, а файл без точки
для него — обычный файл. Это было исправлено в коммите `df859de`.
